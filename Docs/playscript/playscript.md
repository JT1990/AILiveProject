- `SKIP*` 是已知应有逻辑，但是在编排时跳过。`SKIP*` 只是简单示意，也可能有错误/缺失，此次的目的之一就是完善SKIP的逻辑。
- `待补充动画`：继续必备待补补充动画，从 `Mixamo.com` 下载动画资产。
- `GameHoster`的职责：1. 代码逻辑上广播任务给NPC，2.编排时语音播报。
- `逐幕编排`：从开始逐步推演，没通过一幕再推进下一幕。
- LLM请求耗时不记入游戏时间，请求LLM时游戏时间不流逝。
- AI不同时说话

## AI的发言逻辑设计

除非游戏环节为轮流发言，否则不存在“轮流发言”的情况。

### 为什么这样设计？

按照正常的电影/综艺，同时也符合正常的人类社交习惯，不可能多个人同时发言，多数情况下是1个人发言。

以下是僵尸游戏综艺的字幕内容：

```
李尚敏：我已经完全了解这个游戏了！
崔正文：是什么样的游戏？
李尚敏：我不能说。我不能说。
洪榛浩：就是僵尸游戏啊。
金九拉：说得对。但就算你说你知道，如果你不是僵尸也没任何意义。
李尚敏：不是的，哥，我只要避开僵尸就行了。
金九拉：你打算怎么做到？
李尚敏：这就是这个游戏的精髓。
金九拉：看面相吗？
李尚敏：通过避开僵尸、只跟人类接触，提高胜率！
李尚敏：我赌一个石榴石‘崔正文是僵尸’
崔正文：啊 真的吗?是给我吗?如果不是(僵尸)的话?
李尚敏：如果是的话你会给我吗?游戏结束之后?
崔正文：真的吗?那我们要写保证书吗?
李尚敏：是的
崔昌烨：正文啊，你“是人类?还是人啊?？
崔正文：我是女人～
崔昌烨：你是人类还是……人？最开始我想和正文合作的，但是我信不过正文，她一直在神神叨叨地说些可疑的话。
```

发言不是"调度问题"，是事件流：第一句话产生后，它本身变成新的事件，触发别人的反应；反应又触发反应。

### 如何设计

```
开口阶段(种子):
  10路并发 → 每个AI输出{意愿,内容}
  选最高意愿者播放
  其余9个AI的"未说出口内容"暂存进各自记忆

反应阶段(循环):
  广播刚才那句话给9个AI(连同他们各自的"未说出口")
  10路并发 → 每个AI输出{是否接话,接话意愿,接话内容}
  选意愿最高者播放(可能没人想接,则结束)
  循环
```

### 反应链怎么终止？

在当前测试验证阶段，不考虑代码或强制终止，先跑起来几轮再讨论怎么终止，
